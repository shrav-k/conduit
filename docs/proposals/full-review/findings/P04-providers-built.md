## FR-305

**Where should the gate before a run on another machine live?**

P04 I3 · question-for-owner · verifier: partly · decides: owner

(a) As built: on the engine's machine, inside the provider. Nothing is installed on the other machine. Every run there ends when the engine restarts or the SSH session is lost for 30 seconds, and the HTTPS hop is between the engine and its own child process.
(b) On the run's machine: Conduit ships its gate as one small program, and the existing tool starts it beside the run (systemd-run over ssh now, docker run later). The run outlives engine restarts and network losses; the gate ends the run after a stated time cut off, which is PRV-021's own example; the provider keeps no state, which is PRV-027's own example, and shrinks toward three commands over ssh.
