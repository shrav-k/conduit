# Ruling 65: the public name is ConduitLang

Status: in force; directive (A76: owner's account steps) (ruled by the owner on 2026-11-10). Holds now: [IN_FORCE.md: 3. Vocabulary and the project's names](../../../IN_FORCE.md#3-vocabulary-and-the-projects-names), [IN_FORCE.md: 14. Publication and organization](../../../IN_FORCE.md#14-publication-and-organization). This record says why.

This is the record of a
ruling. Where it and the specification differ, the specification governs. It answers ruling 47's
open point on the public name; the namespace follows when the organization exists.

Ruling 64 asked for a public name that is a logical variation on "Conduit". A research workflow
checked eighteen candidates for a free GitHub organization, domains, crates.io and npm names, and
clashes. It recommended ConduitLang, with every main domain unregistered and no notable clash; the
runner-up was ConduitSpec, whose `.com` is held. The owner: "Sounds good on conduitlang, but I'm
unable to take those actions quite yet, write up a doc on action items to switch to conduitlang and
how to set each step up".

## The decisions

- **The public name is ConduitLang**, spelled `conduitlang` everywhere: the GitHub organization
  `conduitlang` (with `conduit-lang` reserved, empty), the domain `conduitlang.dev` when bought, the
  npm scope `@conduitlang` and the crate prefix `conduitlang-`. The language stays **Conduit**.
- **The steps wait for the owner**, who sets up the accounts when able, following
  [the guide](../../guides/move-to-conduitlang.md). Until the organization exists the identifiers
  stay `github.com/shrav-k/conduit/...`; then one command moves them.
