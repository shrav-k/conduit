# Enrollment handoff to 049a

Apply the exact [049a.patch](049a.patch), from the repository root, after
[036b's 048a.patch](../036b-staged/048a.patch). It also applies with [049b.patch](049b.patch)
already present. Neither patch depends on the other's hunks; no close hunks required moving.

This lands enroll-machine.v1, admit-machine.v1 and refuse-machine.v1 together in
object-management.v1, management.v1 requires, root-management and engine implements, with
the capability's head comment and the core README's operation rows. TPL-004 requires the
four lists to move together. The six contracts and exports are already live. The verbs are
engine-implemented, reservedToRoot and never deduplicates. The engine gains three tools only
when this patch and their build land; there is no rerun stub.

Order 072's `every_engine_operation_is_executable_or_unfinished_with_its_order` test is absent
in 038b's tree. Landing implements obliges 049a to add all three verbs to one of the shell's
two lists, executable or unfinished with its order, wherever that test is then present.

Build machines.rs, MachineReport and the provider-call intents against ENR-001 to ENR-012,
PND-008 and PRV-005. The revised list-machines.v1 and place.v1 shapes are in 049b.patch;
049a may use those input shapes while building MachineReport. Land provider capability and
checker changes together with that patch; do not copy part of a capability list in isolation.
Evidence and join actions use the panel channel only. OPS-008's private invocation digest
covers the typed fingerprint; no request or provider-call record stores it or a join action.
The answer holds provider-reported evidence, comparison/exception status and the flag.

For URL enrollment, once the provider succeeds and its declared kinds pass ENR-001, open and
raise once. Client acceptance, decline and cancellation on retry all succeed with the two
IDs, with no account polling. DL18 without retry also succeeds with those outputs. A client
without URL capability receives the IDs immediately, no -32021 (IFC-049). A secret-bearing
URL or any command stays at the panel. Use K1's requestState, never elicitationId.
