# Enrollment handoff to 049b

Apply the exact [049b.patch](049b.patch) after [036b's 048a.patch](../036b-staged/048a.patch),
from the repository root. It applies alone or after [049a.patch](049a.patch), and both orders
commute. No hunk was moved to 049a for proximity. Build order 049a may need the provider
report shapes for MachineReport; the independent patch makes those shapes available without
coupling root operation lists to provider capability lists.

This lands list-machines.v1's required opaque id, pending state, enrollment and evidence;
place.v1's output id; and the three provider operations in machine-provider.v1. The six new
Operation contracts are already live. Reading 18 edits the existing operations in place at
0.1.0; its explicit exception lands in the core README with these edits, never before them.
No shipped package supplies a machine provider.

The patch also adds enroll.v1, accept-machine.v1 and remove-machine.v1 to CALLED_OPERATIONS
in tools/check_schemas.py. That tuple drives PRV-004, PKG-020 and PKG-030. It must change
with machine-provider.v1 so checker and engine agree before and after landing. The engine's
check in engine/crates/core/src/packages.rs reads the capability's operations, so it follows
this patch without a code edit. Both patches keep the TPL-004 engine lists coherent.

Build the fixture provider package and snapshot. It is a Resource owned by system, on local,
reached by provider calls, and offers the complete machine-provider.v1. Its contract states
id derivation, fingerprint alphabet, where each item can be read, label binding, coordination
server pinning and join attribution (ENR-002). CONFORMANCE.md records DL5's enrollment maximum
and report timing and the existing DL6/DL13 choices; 038b does not rewrite those trust promises.
