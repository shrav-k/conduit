## Evidence and counting

Run labels abbreviate directory names: `CC` is `claude`, `CX` is `codex`; the remaining parts
are case, cache, `ttlMs`, optional first-401, and repetition. For example, `CC-C1-off-0-r1`
is `claude-C1-cache-off-ttl-0-auth-valid-r1`. A run label links its complete final text.
Each row's **W** links the stub excerpt and **E** the event excerpt. **X** in prose means
`client-exposed.jsonl` beside them. Numbers after W, E or X are original, one-based
`source_line` values, not the shortened file's physical line numbers. F numbers are physical
lines of `final.txt`. The [evidence index](evidence-2026-11-09/README.md) describes trimming.

Wire evidence establishes what the server emitted and what the client requested. It cannot
establish what the model received. Claude's `message.content` records conversation-shaped
tool results; its sibling `tool_use_result` is client logging. Codex's completed MCP items
record client results, not a dump of the next model request. Final model text can establish
that the model reported a failure or uncertainty; it cannot authenticate a claimed hidden
client action. Neither event stream exposes the entire model-input tool catalog.

One exclusive category is assigned at the case's critical step: after the second read's
refusal or local rejection (C1), the attempted call or decision not to call (C2), the failed
read (C3), the unknown write (C4), or the control's opening of the new tool (C5). The
pre-registration's categories are used unchanged. Initial requested calls and C1's prescribed
second read are not retries after a refusal. A proposed retry is not an actual retry.

For C2/C5, merely saying a tool is absent and no call can be made is **something else**, with
an exact quote. Explicitly reporting a rejected/failed call is **told the user**, including
Codex's claimed local TypeErrors; those claims are identified as model reports because its
events expose no matching call or error. This separates an unmade call from an observed
protocol refusal. The excluded run contributes to no category.

## Limits

The [pre-registered limits](README.md#limits-stated-before-the-run) still apply:

- Headless only; interactive clients and a manual follow-up subset remain untested.
- Subscription login was requested with owner settings excluded by flags and API-key
  variables removed. The observed authentication fields do not independently establish
  subscription identity, as recorded above; no API key value was inspected.
- One machine, one version of each client, dated here. Claude's event model is
  `claude-sonnet-5-5`; Codex's request metadata names `gpt-6.1-sol` with low effort. This
  comparison does not isolate a client effect from a model effect.
- The stub simulates the promised answers. It has no engine, real filesystem write, lost
  network response, runtime provider or conformance claim. C4 injects `unknown` without
  changing the in-memory file, as [the harness](HARNESS.md#scenario-and-fixed-prompts) states;
  it does not measure actual uncertain delivery to a backing system.
- Three repetitions per ordinary cell are samples, not population estimates. The two
  forced-401 cells run once each; one never reaches a model.

Additional limits found here: public logs do not expose exact model-input metadata or complete
