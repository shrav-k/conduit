# 009 — Native launch and identity: results, 2026-11-09

The third attempt completed all nine scenarios: twelve Agent sessions and twenty-four turns.
Both unchanged clients reached the stub with their assigned identities and used newly opened
access on the second turn. The first two attempts each failed in all six scenarios involving
Codex, before its first model turn. They are results too. This is A4, under the
[pre-registration](README.md), with no Conduit engine running.

The launch works with the runner's restricted environment after a Codex-specific helper
change. The records do **not** establish every requested configuration and login property:
Claude Code reports a stub-only tool catalog, but no complete account authentication report;
Codex reports neither a startup catalog nor its authentication. Incoming messages were not
tested. These limits remain work for increment 3; marking the probe done does not settle them.

do not independently audit every file read. This exercises PRV-022/023's loopback launch,
not every file or TLS property of PRV-022.

## Limits

- One machine, one operating-system user, one headless mode and the two recorded client
  versions. Processes under that user can read each other's credentials. Attribution does
  not establish isolation, a bypass boundary or behavior with four separate accounts (A5, A7).
- A stub and a probe runner stand in for an engine and its runner. No real Conduit lifecycle,
  runtime provider, gate, cross-machine connection, TLS or engine restart was exercised.
  The launch source supplies an empty loopback trust bundle; no TLS identity claim follows.
- Successful turns are observations, not a complete settings audit. The missing Codex startup
  catalog, incomplete login reports, absent loaded-source inventories and untested inbound
  message refusal leave the qualifications in points 3, 4 and 7 open.
- No independent process environment capture, helper environment dump or per-file read audit
  is present. The source and plans explain the launches; admitted requests and model events
  substantiate successful use. The admin's diagnosis supplies the missing-variable cause of
  attempt 1 beyond the recorded helper exit.
- Access was closed and opened together between turns. The probe does not distinguish those
  changes independently, measure convergence time, test an in-flight revocation, force a 401
  or test token rotation. Codex's fresh connection explains its second-turn discovery; Claude
  still tried the closed tool despite a successful notification.
- The admin changed the harness between attempts. Counts describe three successive setups,
  not twenty-seven repetitions of one fixed launch. Evidence is trimmed and sanitized, not
  a complete transcript or a source snapshot of the first two harness versions.
