## Claude Code

Source: Claude Code's [Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)
page. Claude Code on a Pro or Max plan is under Anthropic's
[Consumer Terms](https://www.anthropic.com/legal/consumer-terms).

- OAuth, the subscription login, "is intended exclusively for purchasers of Claude Free, Pro,
  Max, Ultra, Team, and Enterprise subscription plans and is designed to support ordinary use of
  Claude Code and other native Anthropic applications."
- "Developers building products or services that interact with Claude's capabilities,
  including those using the Agent SDK, should use API key authentication". Anthropic "does not
  permit third-party developers to offer Claude.ai login into their own applications, or to
  route requests through Free, Pro, Max, or Ultra plan credentials on behalf of their users",
  and developers "may not collect, store, or intermediate Claude.ai credentials or session
  tokens — sign-in to a Claude account must complete through Anthropic's own flow."
- That "does not ... prevent an end user from signing in to the unmodified Claude Code binary
  with their own Claude subscription, including where a platform hosts Claude Code".
- A product that runs Claude Code needs the Commercial Terms and: "The Claude Code binary must
  not be modified", and customers "may not remove, disable, or restrict any authentication
  method built into it".
- "Advertised usage limits for Pro, Max, and Ultra plans assume ordinary, individual usage of
  Claude Code and the Agent SDK."

## Codex

Sources: Codex's [non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode)
and [account auth in CI/CD](https://learn.chatgpt.com/docs/auth/ci-cd-auth). OpenAI's
[terms of use](https://openai.com/policies/terms-of-use/) could not be fetched (HTTP 403); a
search showed that they forbid to "automatically or programmatically extract data or Output"
and sharing account credentials, in wording not checked against the live page.

- "`codex exec` reuses saved CLI authentication by default." "API keys are the right default
  for automation because they are simpler to provision and rotate." ChatGPT sign-in for
  automation is documented as "an advanced workflow for enterprise and other trusted private
  automation"; "Do not use this workflow for public or open-source repositories."
- On the login file: "Do not share the same file across concurrent jobs or multiple machines."
  "Use one `auth.json` per runner or per serialized workflow stream." A reason to seed it again
  is that "another machine or concurrent job rotated the token first."

## What this establishes

| Case | Claude Code | Codex |
| --- | --- | --- |
| The owner runs the engine on their own machine, with their own login, each client unmodified and signed in through its own flow (the first build) | Allowed as read: the owner is the end user of an unmodified binary on their own subscription, and the engine never reads, stores or passes the login. Many Agents at once on one plan strains "ordinary, individual usage", a limit on volume, not a prohibition | Allowed as read: `codex exec` with a ChatGPT login is a documented, trusted private automation. The vendor recommends API keys |
| v0 published, each user running it with their own logins | Allowed under the same reading, the platform-hosting sentence above. If Conduit is offered as a product that runs Claude Code, the Commercial Terms apply and no built-in authentication may be removed or restricted | As above, for private use; OpenAI's terms on automated use were not read whole |
| Conduit, or anyone, holding one login for many users | Not allowed | Not allowed: account credentials are not shared |

Two consequences for the build:

1. **The Agent packages remove the API-key variables** to force the subscription login (work
   order 023). Under Claude Code's terms for products that run it, removing or restricting a
   built-in authentication method is not allowed. The coordinator's reading: an Agent Type
   should offer the API key as a choice of its configuration, the subscription by default,
   rather than always strip it. Not yet changed.
2. **A Codex login cannot be copied into each Agent's home.** OpenAI says one `auth.json` per
   runner, and that another copy rotating the token makes the others stale. The owner's
   direction for finding 3-07, a login as a credential in a pool, therefore holds one copy per
   Codex Agent, each from its own sign-in, or one copy used by serialized Agents; not one copy
   shared.

**Verdict for A8:** the planned use is confirmed for the owner's own engine and for each user
running v0 with their own logins, with API keys named as the alternative both vendors
recommend for automation. To be read again before v0 is published, with OpenAI's terms of use
read whole.
