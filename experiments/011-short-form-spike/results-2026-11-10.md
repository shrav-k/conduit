## Diagnostic probe and stable names

A separately labeled probe drops only `as` from the rendered submission:
**14 passed, 0 failed** through the strict loader and pure core. Each registration
starts from an independently used fresh first-start state with root's existing
management authority, as the conformance runner's submitted-project route does.
The harness checks the authored pins against computed hashes of the four retained
Conduit archives and supplies their loader-validated package snapshots.

Seven comparisons show that flow and block inputs produce identical manifests,
exact translated documents, and probe stored objects. Stored Conduit operations
and resolved ends match S1: A reads and B writes at T1/T2, the access lists swap
at T4, both retain their intended history access, and T7 removes only A's project
Conduit before restoring the previous exact documents. These are registration
checks; no Conduit was opened and no request exercised access.

Four stable-name comparisons pass, T5 and T6 in each style:

- **T5:** the exact document sets and bodies are identical. Only the filesystem
  manifest pin changes, to 0.2.0 with digest
  `sha256:cbb831f07d2b251c84fcd768a03353203a8a1b2215e862881fef47f866d84436`.
  The probe's `shared` and `shared--t` select npm filesystem 2.2.0 instead of
  2.1.0 for all three operations. History still selects 2.1.0 through its own
  package's 0.1.0 pin. Operation lists remain the original three; no append or
  copy operation enters them.
- **T6:** the only changed exact document is `shared--t`, at `/spec/config/root`,
  from `/lab/shared` to `/lab/replacement`. The probe changes only the shared
  template's definition and the shared Resource's configuration.
- In the probe, every other stored field is compared after removing `held`
  resolver contexts and `packages` pin lists. Every object name remains equal;
  both project Conduits resolve to the shared Resource at each state.
  The changed definition set is exactly `shared`, `shared--t`. A real stable-name
  replacement must retire and remove the old shared Resource, update its template,
  make its new instance, and recreate its two incoming project Conduits under their
  existing names. This spike checks the resulting definition difference, not those
  lifecycle requests.

Dropping `as` changes meaning: today's kernel uses the standalone Conduit's full
name for its tool prefix, for example `agent-a--project.*`, rather than
`project.*`. This probe isolates the unsupported field; it is not a successful
implementation of the translation table or its as-if claim. Held contexts and
pins differ on fresh registration beyond the replacement objects; no comparison
here establishes their preservation during a real update.

## Limits and checks

This is an offline Rust translation experiment and a paper count, **not an S1
author run** under [ruling 45](../../docs/proposals/ruling-45/README.md).
Paths are supplied literal values; no directories are created. There are no real
Agents, tools, installs, approvals, plan execution, live access changes, tombstones,
Fleet, shutdowns, windows without access, observations of time or mistakes, or
measurements of repair effort. Package snapshots are available without fetching.
The exact translations fail, and removing the rejected field loses the intended
tool prefixes. The kernel and language have not been extended by this experiment.

The proposed commands use an unimplemented planner interface. Their syntax and
flag sufficiency need specification/tooling work; they are listed to expose the
paper cost assumption. They do not replace today's actual author commands.
Tests cover expansion rows and reject selected invalid shorthand inputs; source
mapping, the full strict shorthand language and provider behavior are outside
this small spike, as the README states.

All **8 required checks passed, 0 failed**. The Rust suite has **9 tests passed,
0 failed**; one asserts the 14 exact rejections, so its success is not a claim of
